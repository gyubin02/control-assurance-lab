# 322개 테스트가 통과한 뒤 다시 멈춘 이유

탐지·대응·복구 실행 모델을 붙인 뒤 전체 테스트 322개가 통과했다. 그대로
커밋하지 않고, “파일을 전부 고쳐 쓰고 해시도 다시 만든 사람이 이 증거를
속일 수 있는가?”라는 기준으로 한 번 더 읽었다.

세 군데에서 같은 종류의 실수를 발견했다.

## 탐지

코드는 이벤트를 `forwarded_events`에 넣었지만, fallback 경보를 만들 때는
그 테이블을 다시 읽지 않고 원래 `source_events`를 사용했다. 전달됐다는
ID 목록과 경보가 각각 맞아 보일 뿐, **전달된 레코드가 실제로 경보의
입력이었다**는 연결은 없었다.

`closed_at_ms = 2000`도 직접 써 넣었다. 시계가 2초까지 진행됐는지, 탐지기가
마지막 이벤트까지 처리했는지, 대기열이 비었는지는 읽지 않았다. 이 상태의
빈 검색 결과로 “named alert 없음”을 결론 내릴 수는 없다.

## 대응

fresh clone ID는 SQLite 실행이 끝난 뒤 문자열로 만들었다. DB 안에서 그
값을 읽은 적이 없었다. cleanup도 연결을 닫은 뒤 실제 쿼리가 실패했는지
확인하지 않고 `verified`라고 기록했다.

더 큰 문제는 stage event가 `session_active=true` 같은 요약값만 담았다는
점이다. 검증기는 selector로 기대값을 다시 계산해서 그 요약과 비교했다.
둘이 맞아도 실제 session 행을 읽었다는 증거는 아니었다.

## 복구

세션 교체 상태는 새 DB를 만들 때 기대값으로 넣고, 바로 다시 읽은 뒤
“독립적인 readback”이라고 불렀다. 복구 전 lifecycle snapshot과 이어지는
식별값이 없었다.

이전 disclosure도 숫자 하나를 받아 같은 숫자를 반환한 뒤 “보존됨”이라고
했다. 호출자가 7 대신 0을 넘겨도 둘 다 통과한다. 보존해야 할 것은 단순한
개수가 아니라 정확한 ledger 내용의 식별값이다.

## 수정 기준

- 전달 경로의 다음 단계는 원본이 아니라 전달 테이블의 readback을 입력으로
  사용한다.
- 음성 증거는 시계, 처리 watermark, 빈 대기열, query 시점을 함께 닫는다.
- clone과 cleanup은 문자열 주장이 아니라 DB readback과 실패한 close probe로
  확인한다.
- 요약값보다 아래에 있는 행, 변경 건수, query/decision receipt를 남긴다.
- lifecycle history는 count가 아니라 정확한 ledger digest로 연결한다.

초록색 테스트는 “우리가 써 둔 기대를 코드가 반복한다”는 것까지도 잘
검사한다. 그래서 이번에는 테스트 개수가 아니라, 서로 다른 기록을 연결한
사람이 거짓말을 하려면 어떤 원시 사실까지 함께 위조해야 하는지를 기준으로
다시 만든다.

## 독립 감사에서 다시 멈춘 지점

위 수정을 마친 뒤에도 끝난 것은 아니었다. 다른 사람이 결과 파일을 통째로
다시 쓴다고 생각하고 같은 공격을 반복했다.

- responder 설정 해시는 실행 전후가 서로 같은지만 확인했다. 둘 다 엉뚱한
  해시로 바꾸면 통과했다. 이제 검증기가 알고 있는 정확한 설정 원문과
  비교한다.
- recovery의 두 target을 서로 다른 CAB에서 가져올 수 있었다. 한쪽 CAB의
  과거 유출 이력을 지우면 서로 다른 사건을 비교하는 셈인데도 결과가
  나왔다. 이제 두 target은 하나의 사건과 하나의 CAB를 공유해야 한다.
- `apply receipt valid=true`라는 요약을 다시 계산하지 않는 경로가 있었다.
  operation ID와 변경 건수를 함께 바꾸면 실제 변경 없이도 복구를 했다고
  꾸밀 수 있었다.
- clone 이름과 nonce도 그 값을 사용한 모든 이벤트를 같이 고치면 통과했다.
  실행 때 DB에서 읽은 identity와 평가 때 재계산한 identity를 다시 잇는다.

여기서 배운 것은 간단했다. “해시가 맞다”는 말은 알려진 올바른 값과
비교했을 때만 의미가 있다. “두 실행을 비교했다”는 말도 두 실행이 같은
과거에서 갈라졌을 때만 의미가 있다. 그리고 `valid`라는 필드는 증거가
아니라, 언제든 다시 계산해야 하는 결론이다.
